## WebSocket 前端部署与排错过程（14:40-15:32）

### 排除的多个问题
1. **VITE_WS_URL 为 localhost**：Docker build 时未传入正确参数 → 通过 `SERVER_IP=101.35.231.154 docker compose up -d --build frontend` 解决
2. **用户访问 :80 而非 :3000**：前端通过 api-gateway(:80) 的 frontend 服务暴露，不是独立的 :3000 容器
3. **api-gateway nginx 缺 /ws 路由**：旧配置未包含 websocket_upstream → `docker compose restart api-gateway` 解决
4. **HTTP Authentication failed (401)**：JWT Secret 不匹配！config.go 中 `cfg.Server.JWTSecret` 和 `cfg.JWT.Secret` 默认值不同（`elderly-health-care-secret-key-2024` vs `elderly-health-care-jwt-secret-2024`）→ 统一为后者并重建 admin-auth-service + websocket-service

### 最终验证结果 ✅
- MQTTX 发送 `device/EH-WATCH-20260101/online` 消息
- 浏览器控制台显示 `[WebSocket] Received: device_online` + `[DeviceManage] Device online event received`
- 整条链路打通：MQTTX→EMQX→websocket-service→WebSocket(WS鉴权)→wsStore→DeviceManage组件事件处理
- 页面自动刷新触发（因模拟消息未写库，数据无变化属预期行为）

### 关键经验总结
- Docker Compose 中 `args.VITE_WS_URL: ws://${SERVER_IP:-localhost}/ws` 必须显式设置 SERVER_IP 环境变量
- config.go 中 JWT Secret 有两处默认值必须保持一致（Server.JWTSecret vs JWT.Secret）
- api-gateway 重启才能加载最新的挂载配置文件

## 前端 DeviceManage 页面白屏修复（18:11-21:30）

### 问题现象
浏览器 Console 连续报 TypeError：
1. `Cannot convert undefined or null to object` at `Object.values(deviceOnline)` — deviceOnline 为 undefined
2. `Cannot read properties of undefined (reading 'filter')` — data 数组为 undefined
3. WebSocket 连接 `ws://localhost/ws` 失败（code=1006）— WS 地址错误

### 修复内容（3 轮迭代）
**第 1 轮**：`DeviceManage.tsx` 中 `Object.values(deviceOnline)` → `Object.values(deviceOnline ?? {})` + 属性访问加 `?? {}`
**第 2 轮**：所有 `data.filter(...)` → `(data ?? []).filter(...)`，共 5 处空值兜底
**第 3 轮（根因）**：`.env.production` 和 `.env.development` 中 `VITE_WS_URL=ws://localhost:80/ws` 改为 `ws://101.35.231.154/ws`

### 根因分析
Vite 构建时将 `.env.production` 中的 `VITE_WS_URL` 硬编码到 JS bundle 中。本地构建时该值指向 localhost，导致：
- 浏览器连本地 80 端口 → 无服务监听 → WS 1006 断开
- deviceOnline 始终为空对象 → Object.values(null) 报错 → React 组件崩溃白屏
