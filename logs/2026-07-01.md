### 报警数据不入库根因修复（14:48）— 🔑 核心问题

**问题现象**: AlarmManage 页面 WS 消息正常收到 → 触发 loadData() → 但 API 返回 `{"data":null,"total":0}` → 列表始终为空

**完整链路诊断**:
```
✅ MQTT 消息发布到 device/+/alarm topic
✅ websocket-service 收到 → parseAlarmData → BroadcastToAll(new_alarm) → 前端收到
✅ 前端 ws:message 事件触发 → setRealtimeAlarm + loadData()
✅ 前端调用 GET /api/v1/alarms?page=1&page_size=8
❌ 后端查询 alarm_records 表 → 返回空（因为记录从未写入！）
```

**三个后端 Bug** (device-service `handleAlarmForward` 函数):

| # | Bug | 严重程度 | 说明 |
|---|-----|---------|------|
| **1** | **nil 指针 panic** | 🔴 致命 | `*alarm.Latitude`/`*alarm.Longitude` — 当 MQTT 消息不含经纬度时解引用 nil 指针 → goroutine 崩溃 → INSERT 不执行 |
| **2** | **字段名不兼容** | 🟠 高 | JSON 发 `level`，Go struct 读 `severity` → severity 为空字符串 |
| **3** | **Exec 错误被吞** | 🟠 高 | `database.DB.Exec()` 返回值完全忽略 → SQL 执行失败也无感知 |

**修复方案** (`backend/internal/device/handler.go`):
- 改用 `map[string]interface{}` 接收原始 JSON（不依赖结构体）
- 兼容 `level` / `severity` 两种字段名
- 经纬度字段做 nil 检查后才解引用
- `database.DB.Exec()` 增加 `(result, err)` 错误检查和日志输出
- 新增辅助函数: `toFloat64()`, `getFloat()`, `getInt()`

### 报警数据不入库 v4 — FK 外键验证修复（16:43）

**根因确认**（服务器日志铁证）：
```
❌ [Alarm] INSERT failed!
Error 1452: foreign key constraint fails (`alarm_records`, 
CONSTRAINT `fk_ar_elderly` FOREIGN KEY (`elderly_id`) REFERENCES `elderly_profiles`(`id`))
elderly_id = 6b6af9f8-74ff-11f1-a296-0242ac130012   ← 在 elderly_profiles 表中不存在！
```

MQTT 消息带的 `elderly_id` 是个**无效外键值**（不为空但指向不存在的记录）。v3 只在空字符串时反查，漏掉了这种场景。

**v4 修复策略**（`handleAlarmForward` elderly_id 验证段）:
| 层级 | 触发条件 | 操作 |
|------|---------|------|
| L1: 直接验证 | `elderly_id != ""` → `SELECT COUNT(*) FROM elderly_profiles WHERE id=?` | 存在则用，否则降级 |
| L2: device_sn 反查 | L1 失败 + 有 device_sn → 查 devices 表 | 找到后再二次验证 |
| L3: 兜底 fallback | L2 也失败 → `SELECT id FROM elderly_profiles LIMIT 1` | 取第一条（开发测试用） |
| L4: 最终检查 | 所有方法都找不到 validElderlyID | 打 ❌ 错误并 return |

**版本标记**: `v20260701-1643 (alarm-db-fix-v4-fk-validate)`
