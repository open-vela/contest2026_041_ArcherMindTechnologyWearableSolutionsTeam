### 1.2 三种方案对比

| 维度 | 方案一：Nginx 静态 | 方案二：Docker+Nginx | 方案三：Docker Compose |
|------|-------------------|---------------------|----------------------|
| **适用场景** | 传统服务器 / 虚拟机 | 容器化环境 | 全栈一键部署 |
| **上手难度** | ★☆☆ 低 | ★★☆ 中 | ★★☆ 中 |

| **推荐场景** | 已有 Nginx 服务器 | K8s / 云原生 | 开发/演示/小规模 |

## 2. 方案一：Nginx 静态部署

### 2.1 前置条件

| 软件 | 最低版本 | 用途 |
|------|---------|------|
| Node.js | 18.x | 构建前端 |
| npm | 9.x | 包管理 |
| Nginx | 1.24+ | Web 服务器 |

### 2.2 构建步骤

```bash
# 1. 进入项目目录
cd web-admin-react

# 2. 安装依赖
npm install

# 3. 构建生产版本（输出到 dist/）
npm run build

# 构建产物：
# dist/
#   ├── index.html
#   ├── assets/
#   │   ├── index-<hash>.js      (主 JS，~300KB gzipped)
#   │   ├── index-<hash>.css     (样式，~50KB gzipped)
#   │   └── antd-<hash>.js       (Ant Design，按需加载)
#   └── favicon.svg
```

### 2.3 Nginx 配置

将 `deploy/nginx.conf` 复制到 Nginx 配置目录：

```bash
# Linux
sudo cp deploy/nginx.conf /etc/nginx/sites-available/elderly-admin
sudo ln -s /etc/nginx/sites-available/elderly-admin /etc/nginx/sites-enabled/
sudo nginx -t && sudo nginx -s reload

# Windows
copy deploy\nginx.conf C:\nginx\conf\conf.d\elderly-admin.conf
nginx -t && nginx -s reload
```

配置核心内容：

```nginx
server {
    listen       80;
    server_name  admin.elderly-care.com;

    # 静态文件根目录
    root   /var/www/elderly-admin;
    index  index.html;

    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml;

    # 静态资源强缓存（带 hash 的 JS/CSS 可永久缓存）
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # SPA 路由：所有非文件请求回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://backend-api-gateway:80;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # WebSocket 代理
    location /ws {
        proxy_pass http://backend-api-gateway:80;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

### 2.4 部署文件

```bash
# 复制构建产物到 Nginx 静态目录
sudo mkdir -p /var/www/elderly-admin
sudo cp -r dist/* /var/www/elderly-admin/
sudo chown -R www-data:www-data /var/www/elderly-admin
```

## 3. 方案二：Docker + Nginx 部署

### 3.1 镜像构建

使用多阶段构建的 `Dockerfile`（已提供 `deploy/Dockerfile`）：

```dockerfile
# ---- Stage 1: 构建 ----
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build

# ---- Stage 2: 运行 ----
FROM nginx:1.25-alpine
COPY deploy/nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget --quiet --tries=1 --spider http://localhost/ || exit 1
CMD ["nginx", "-g", "daemon off;"]
```

### 3.2 构建与运行

```bash
# 构建镜像
docker build -t elderly-admin-web:latest -f deploy/Dockerfile .

# 运行容器（映射到 80 端口）
docker run -d \
  --name elderly-admin-web \
  -p 80:80 \
  --restart always \
  elderly-admin-web:latest

# 查看日志
docker logs -f elderly-admin-web
```

### 3.3 镜像推送到仓库（可选）

```bash
# 标记并推送到私有仓库
docker tag elderly-admin-web:latest registry.example.com/elderly-admin-web:v1.0.0
docker push registry.example.com/elderly-admin-web:v1.0.0
```

## 4. 方案三：Docker Compose 全栈集成部署

### 4.1 集成架构

在原有后端 `docker-compose.yml` 基础上，新增前端服务：

```
services:
  # ... 原有后端服务 (mysql, redis, emqx, 8个微服务, api-gateway) ...

  # ============ 前端 Web 管理台 ============
  web-admin:
    build:
      context: ../web-admin-react
      dockerfile: deploy/Dockerfile
    container_name: ehc-web-admin
    restart: always
    ports:
      - "3000:80"
    depends_on:
      - api-gateway
```

### 4.2 独立前端 docker-compose

已提供 `deploy/docker-compose.frontend.yml`，可独立启动前端：

```bash
cd web-admin-react
docker compose -f deploy/docker-compose.frontend.yml up -d
```

### 4.3 全栈一键启动

集成了前端的完整 `docker-compose` 已提供在 `deploy/docker-compose.fullstack.yml`：

```bash
# 从 outputs 目录执行
cd outputs

# 启动全栈（后端 + 前端）
docker compose \
  -f backend/deploy/docker-compose.yml \
  -f web-admin-react/deploy/docker-compose.fullstack.yml \
  up -d

# 访问地址
# 管理台:    http://localhost:3000
# EMQX 面板: http://localhost:18083
# API 网关:  http://localhost:80/api/v1
```

## 6. HTTPS 与域名配置

### 6.1 使用 Let's Encrypt 免费证书

```bash
# 安装 Certbot
sudo apt install certbot python3-certbot-nginx

# 自动配置 Nginx + HTTPS
sudo certbot --nginx -d admin.elderly-care.com

# 自动续期（Certbot 会自动添加 cron 任务）
sudo certbot renew --dry-run
```

### 6.2 使用自有证书

```nginx
server {
    listen 443 ssl http2;
    server_name admin.elderly-care.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    # 现代 SSL 配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers off;

    # HSTS
    add_header Strict-Transport-Security "max-age=63072000" always;

    # ... 其余配置同 HTTP 版本 ...
}

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name admin.elderly-care.com;
    return 301 https://$server_name$request_uri;
}
```

## 7. 性能优化

### 7.1 构建时优化

| 优化项 | 配置方式 | 效果 |
|--------|---------|------|
| **代码分割** | Vite 自动按路由分割 | 首屏 JS < 200KB |
| **Tree Shaking** | ES Module + Vite 默认开启 | 移除未使用代码 |
| **CSS 提取** | Vite 默认 | 独立 CSS 文件 |
| **压缩** | Vite 默认 esbuild+terser | JS 压缩率 60%+ |
| **图片优化** | 构建前压缩 | （项目暂无图片） |

### 7.2 Nginx 层优化

```nginx
# Gzip 压缩（已包含在 nginx.conf）
gzip on;
gzip_comp_level 6;
gzip_min_length 1000;
gzip_types text/plain text/css application/json application/javascript text/xml;

# Brotli 压缩（比 Gzip 小 20%，需编译 brotli 模块）
brotli on;
brotli_comp_level 6;
brotli_types text/plain text/css application/json application/javascript;

# 静态资源缓存
location /assets/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

# HTML 不缓存（确保更新后用户获取最新版本）
location ~* \.html$ {
    expires -1;
    add_header Cache-Control "no-cache";
}

# HTTP/2（nginx.conf 已启用）
# 多路复用，减少连接数
```

### 7.3 关键性能指标

| 指标 | 目标值 |
|------|--------|
| FCP (First Contentful Paint) | < 1.0s |
| LCP (Largest Contentful Paint) | < 2.5s |
| TBT (Total Blocking Time) | < 200ms |
| 构建体积 (gzipped) | < 500KB |
| 首屏 JS (gzipped) | < 200KB |

## 8. 安全加固

### 8.1 Nginx 安全头

已在 `nginx.conf` 中配置：

```nginx
# 防点击劫持
add_header X-Frame-Options "DENY" always;

# 防 MIME 嗅探
add_header X-Content-Type-Options "nosniff" always;

# XSS 防护
add_header X-XSS-Protection "1; mode=block" always;

# Referrer 策略
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# 权限策略
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

# CSP 内容安全策略
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' ws: wss:; font-src 'self' data:;" always;
```

### 8.2 其他安全措施

| 措施 | 说明 |
|------|------|
| **隐藏版本号** | `server_tokens off;` |
| **IP 白名单** | 可限制管理台访问来源 IP |
| **速率限制** | `limit_req_zone` 限制 API 请求频率 |
| **JWT 认证** | 前端 Token 存储于 localStorage，每次请求自动附带 |
| **HTTPS 强制** | 生产环境必须使用 HTTPS |
| **依赖审计** | 定期 `npm audit`，及时更新依赖 |

### B. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 刷新页面 404 | Nginx 未配置 try_files | 检查 `try_files $uri /index.html` |
| API 请求 404 | 代理路径不匹配 | 确认 `location /api/` 配置 |
| WebSocket 连接失败 | 缺少 Upgrade 头 | 添加 `proxy_set_header Upgrade` |
| 页面白屏 | JS 加载失败 | 检查 `base` 路径配置 |
| 登录后 Token 丢失 | HTTPS 降级问题 | 检查 mixed-content |
| 缓存不更新 | HTML 被缓存 | 设置 `expires -1` for .html |
