# 前端测试文档

## 测试框架

| 工具 | 用途 |
|------|------|
| **Vitest** | 测试运行器（与 Vite 深度集成） |
| **@testing-library/react** | React 组件渲染与交互测试 |
| **@testing-library/jest-dom** | DOM 断言扩展（toBeInTheDocument 等） |
| **@testing-library/user-event** | 用户交互模拟（点击、输入） |
| **MSW (Mock Service Worker)** | API 接口 Mock（拦截 HTTP 请求） |

## 运行测试

```bash
# 运行所有测试
npm test

# 监视模式（文件变更自动重跑）
npm run test:watch

# 生成覆盖率报告
npm run test:coverage

# 可视化 UI（需要安装 @vitest/ui）
npm run test:ui
```

## 注意事项

1. **matchMedia Mock**：antd v5 的 Row/Col 组件依赖 `window.matchMedia`，已在 `setup.ts` 中全局 Mock
2. **MSW 需要在测试前启动**：每个测试文件头部需调用 `server.listen()`，结束后 `server.close()`
3. **Zustand Store Mock**：组件测试中使用 `vi.mock('@/store/...')` 隔离 Store
4. **运行缓慢**：首次运行需要构建 jsdom 环境，后续运行会缓存

## 集成测试（连真实后端）

### 概述

集成测试用于验证前端与真实后端服务器的接口是否正常工作。

**与单元测试的区别**：

| 类型 | 命令 | 是否需要服务器 | Mock | 配置文件 |
|------|------|----------------|------|----------|
| 单元测试 | `npm test` | ❌ 不需要 | ✅ MSW | `vitest.config.ts` |
| 集成测试 | `npm run test:integration` | ✅ 需要 | ❌ 无 | `vitest.integration.config.ts` |

### 配置服务器地址

编辑 `.env.test` 文件：

```bash
# .env.test

# API 服务器地址（根据实际情况修改）
VITE_API_BASE_URL=http://localhost:8080

# WebSocket 地址
VITE_WS_URL=ws://localhost:8080

# 是否使用 Mock（集成测试必须为 false）
VITE_USE_MOCK=false

# 测试用户凭据（需要与数据库中的账号一致）
TEST_USERNAME=admin
TEST_PASSWORD=Admin@2026
```

### 运行集成测试

**前置条件**：

1. 后端服务器已启动
   ```bash
   cd outputs/backend
   docker compose up -d
   ```

2. 数据库中有测试数据（至少包含一个 admin 用户）

3. 确认服务器健康
   ```bash
   curl http://localhost:8080/health
   ```

**运行测试**：

```bash
# 运行所有集成测试
npm run test:integration

# 运行单个集成测试文件
npx vitest run src/api/__tests__/auth.integration.test.ts --config vitest.integration.config.ts
```

### 集成测试文件示例

创建 `*.integration.test.ts` 文件：

```typescript
// src/api/__tests__/elderly.integration.test.ts
import { describe, it, expect, beforeAll } from 'vitest';
import axios from 'axios';
import { INTEGRATION_CONFIG } from '@/test/config';

const apiClient = axios.create({
  baseURL: INTEGRATION_CONFIG.baseURL,
  timeout: INTEGRATION_CONFIG.timeout,
});

describe('集成测试：老人管理 API', () => {
  let token: string;

  beforeAll(async () => {
    // 先登录获取 Token
    const res = await apiClient.post('/api/v1/auth/login', {
      username: INTEGRATION_CONFIG.testUser.username,
      password: INTEGRATION_CONFIG.testUser.password,
    });
    token = res.data.data.access_token;
  });

  it('获取老人列表', async () => {
    const res = await apiClient.get('/api/v1/elderly', {
      headers: { Authorization: `Bearer ${token}` },
    });
    expect(res.status).toBe(200);
    expect(Array.isArray(res.data.data)).toBe(true);
  });
});
```

### 测试模式切换

```bash
# 1. 纯前端测试（不需要服务器）
npm test

# 2. 集成测试（需要服务器）
npm run test:integration

# 3. 先跑单元测试，再跑集成测试
npm run test:all
```

### 常见问题

**Q: 集成测试失败，提示"后端服务器不可达"？**

A: 检查：
1. 后端是否已启动（`docker compose ps`）
2. `.env.test` 中 `VITE_API_BASE_URL` 是否正确
3. 防火墙是否阻止了端口

**Q: 如何在 CI/CD 中运行集成测试？**

A: 在 GitHub Actions / Jenkins 中：
```yaml
- name: 启动后端
  run: cd outputs/backend && docker compose up -d

- name: 等待后端就绪
  run: curl --retry 10 --retry-delay 3 http://localhost:8080/health

- name: 运行集成测试
  run: cd outputs/web-admin-react && npm run test:integration
```

**Q: 能否同时跑单元测试和集成测试？**

A: 可以，使用 `npm run test:all`（先跑单元测试，再跑集成测试）
